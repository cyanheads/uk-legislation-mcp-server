# 0.1.2 — 2026-10-09

## Changed

- **HTTP sessions default to stateless in source** — with `MCP_SESSION_MODE` unset or blank, the server now runs stateless rather than the framework default (`auto`, which resolved to stateful); an explicit `MCP_SESSION_MODE` value still overrides. The Dockerfile and `.env.example` already set `stateless`, so those deployments see no change.
- **`server.json` npm entries** — both entries carried `run start:stdio` / `run start:http` package arguments and the HTTP entry set no `MCP_TRANSPORT_TYPE`. A registry client passes those arguments to the package bin, which ignores them, so the HTTP entry started the stdio transport. The arguments are gone, `runtimeHint` is `npx`, and the HTTP entry fixes `MCP_TRANSPORT_TYPE` to `http`.
- **Hosted endpoint** — `server.json` `remotes` and the README list the public instance `https://uk-legislation.caseyjhand.com/mcp`.
- **Recovery forwarding** — the tools and `LegislationClient` no longer forward declared recovery hints per throw; the framework's contract fill delivers them. The hints callers receive are unchanged.
- **Docker** — production dependencies install in a deps stage on `$BUILDPLATFORM` through the framework's `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts`; the image's contents and runtime are otherwise unchanged.
- **CodeQL** — the workflow runs one job per language.
- **Framework sync** — lint, devcheck, and release scripts, `framework-skills/`, ignore files, `.env.example` entries, and `CLAUDE.md`/`AGENTS.md` match `@cyanheads/mcp-ts-core` 0.13.14.

## Framework

`@cyanheads/mcp-ts-core` ^0.13.8 → ^0.13.14:

- Numeric strings for numeric inputs (`limit`, `page`, `year`, `year_from`/`year_to`) and `null` for an optional field are repaired instead of rejected (0.13.14).
- Tool error results end their text with `request <id>` and carry `data.requestId` (0.13.10).
- Argument-rejection hints name each field's path (0.13.9).
- `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0 (0.13.9, 0.13.11).
